## 3. Key Generation: Encryption and Signing

To achieve the Encrypt-Then-Sign mission, we needed two separate RSA key pairs—one for confidentiality, the other for authenticity.

* Encryption Key Pair (used for RSA-OAEP):
  * Encrypts the message with the public key
  * Decrypts it with the private key
* Signing Key Pair (used for RSA-PSS):
  * Signs the message with the private key
  * Verifies the signature with the public key

No keys, no crypto—so here’s how we made them:

Key Generation & Management Code

```python
def generate_rsa_keypair():
"""Generate an RSA key pair (private & public key)."""
private_key = rsa.generate_private_key(
  public_exponent = 65537,
  key_size = 2048,
)
public_key = private_key.public_key()
return private_key, public_key

```

✅ public\_exponent=65537: a widely used, secure default.

✅ key\_size=2048: strong enough for our message while staying performant.

Save/Load Keys

We saved the keys to .pem files so we don’t have to regenerate them every time (because no one wants to lose their keys halfway through a mission).

Note that in practice, private keys should be protected (e.g., password-encrypted or stored in a secure environment) while public keys can be freely shared—send those out with confidence.

```python
def save_key(key, filename, is_private = False):
"""Save RSA keys to a file."""
if is_private:
  pem = key.private_bytes(
    encoding = serialization.Encoding.PEM,
    format = serialization.PrivateFormat.PKCS8,
    encryption_algorithm = serialization.NoEncryption(),
  )
else:
pem = key.public_bytes(
  encoding = serialization.Encoding.PEM,
  format = serialization.PublicFormat.SubjectPublicKeyInfo,
)



with open(filename, "wb") as f:
f.write(pem)



def load_key(filename, is_private = False):
"""Load RSA keys from a file."""
with open(filename, "rb") as f:
key_data = f.read()
if is_private:
  return serialization.load_pem_private_key(key_data, password = None)
return serialization.load_pem_public_key(key_data)

```

All keys are securely generated and saved to .pem files. Future runs can load them back to avoid regenerating every time. Four keys, two pairs, one mission: keep our message locked down and our identity crystal clear.

## 4. Encrypting the Message (RSA\_OAEP)

To keep our message confidential, we encrypt it using RSA-OAEP (Optimal Asymmetric Encryption Padding). But why OAEP? Well, it’s not just your standard RSA—it enhances the basic RSA scheme with semantic security. This prevents certain attacks, like chosen ciphertext attacks, where an attacker could manipulate encrypted data to try to learn something about the plaintext.

Here’s how we do it:

1. We use the recipient's public key to encrypt the message.
2. We apply RSA-OAEP padding to the message before encrypting, which ensures the message stays secure even if someone tries to mess with it.
   * The padding ensures that even if two identical messages are encrypted with the same public key, their ciphertexts will be different. This guards against potential attackers trying to analyze patterns in encrypted messages.
3. Finally, we encode the encrypted message using Base64, making it easy to send over text-based protocols (like email, or as part of a JSON payload) while ensuring it’s still binary-safe.
   * Once we encrypt the message, it’s binary data. Base64 converts it into ASCII text, which makes it easy to transmit and store, but still keeps the content secure—since only the receiver’s private key can decrypt it.

```python
def encrypt_message(message, public_key):
"""Encrypts a message using RSA-OAEP."""
ciphertext = public_key.encrypt(
  message.encode(),
  padding.OAEP(
    mgf = padding.MGF1(algorithm = hashes.SHA256()),
    algorithm = hashes.SHA256(),
    label = None,
  ),
)
return base64.b64encode(ciphertext)


```

## 5. Signing the Encrypted Message (RSA-PSS)

Once the message is encrypted, we take an extra step to ensure authenticity and integrity: we sign the ciphertext using our private signing key. This is important because if someone tries to tamper with the encrypted message, even by changing a single bit, the signature verification will fail.

For signing, we use RSA-PSS (Probabilistic Signature Scheme) with SHA-256, a modern and secure signing method that guarantees both security and flexibility.

Here’s the signing function:

```python
def sign_message(ciphertext_b64, private_key):
"""Signs the raw encrypted message (bytes) using RSA-PSS."""
ciphertext_bytes = base64.b64decode(ciphertext_b64)
signature = private_key.sign(
  ciphertext_bytes,
  padding.PSS(
    mgf = padding.MGF1(hashes.SHA256()),
    salt_length = padding.PSS.MAX_LENGTH,
  ),
  hashes.SHA256(),
)
return base64.b64encode(signature)


```

## 6. Verifying the Signature Before Decrypting

This is a crucial step. Before we even think about decrypting the message, we verify the signature. This step ensures that the message hasn't been tampered with and that it's genuinely from the sender. If the signature doesn't match, we stop right there—no decryption is attempted. This helps us avoid any potential fake or modified messages.

Here’s how we verify the signature:

```python
def verify_signature(ciphertext_b64, signature_b64, public_key):
"""Verifies the signature against the raw ciphertext bytes."""
ciphertext_bytes = base64.b64decode(ciphertext_b64)  # Convert Base64 → bytes
signature_bytes = base64.b64decode(signature_b64)  # Convert Base64 → bytes



try:
public_key.verify(
  signature_bytes,
  ciphertext_bytes,
  padding.PSS(
    mgf = padding.MGF1(hashes.SHA256()),
    salt_length = padding.PSS.MAX_LENGTH,
  ),
  hashes.SHA256(),
)
return True
    except Exception as e:
print(f"Signature verification failed: {e}")
return False

```

## 7. Decrypting the Message (Only If Verified)

Once the signature has been verified, we proceed to decrypt the message using the private decryption key. This ensures that the original message is securely retrieved and can only be read by the recipient who holds the corresponding private key.

Here’s the decryption function:

```python
def decrypt_message(ciphertext, private_key):
"""Decrypts a message using RSA-OAEP."""
plaintext = private_key.decrypt(
  base64.b64decode(ciphertext),
  padding.OAEP(
    mgf = padding.MGF1(algorithm = hashes.SHA256()),
    algorithm = hashes.SHA256(),
    label = None,
  ),
)
return plaintext.decode()

```

Only the intended recipient with the private key can decrypt it—read it. Confidentiality unlocked.

## 8. Full Secure Messaging Workflow

1. Sender:
   * Encrypts the message using the recipient's public key.
   * Signs the encrypted message using their private signing key.
   * Sends both the ciphertext and the signature.
2. Receiver:
   * Verifies the signature using the sender's public signing key.
   * If valid, decrypts the ciphertext using their private key.

No signature? No decrypt. No authenticity? No trust.
